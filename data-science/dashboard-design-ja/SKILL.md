# ダッシュボードデザインスキル

グラフを描く前に必ずこのルールを適用する。データの正しさは `data-science/data-reconciliation`、レポート文章は `management/client-report-generator-ja` が担当。デジタル庁「ダッシュボードデザインガイドブック」の設計原則をベースに、広告・SEO・経営データ向けに具体化したもの。

## 0. 設計の起点は「問い」

ダッシュボードは「あるデータを全部並べる」ものではなく「誰が・何を判断するために・どの数字を見るか」から逆算する。
- 利用者と判断を1行で定義してから作る(例: 「経営者が月次で広告投資の継続を判断する」)
- 1画面1目的。運用者向けの詳細と経営者向けのサマリを同居させない(ページを分ける)
- 最重要指標(KGI)を左上に。視線は左上→右下に流れる

## 1. チャート選択ルール

| 見せたいもの | 使う | 使わない(理由) |
|---|---|---|
| 時系列の推移 | 折れ線 | 棒の乱立(比較点が多いと読めない) |
| 項目間の比較 | 横棒(項目名が日本語で長いため) | 縦棒は項目6個まで |
| **構成比** | **横棒(100%積み上げ or 並列)** | **円グラフは原則使わない**(角度の比較は不正確。使うなら2〜3項目まで) |
| 目標との対比 | 棒+目標線(リファレンスライン) | ゲージ(面積を食う割に情報が少ない) |
| 2指標の関係 | 散布図 | 二軸グラフは原則避ける(軸の取り方で印象操作になる。使うなら軸ラベルを明示) |
| 単一の重要数値 | スコアカード+前期比 | 数字だけ(比較がないと判断できない) |
| 表 | 詳細参照用に最後へ | ダッシュボードの主役にしない |

## 2. 軸・スケールの規律(誤読・印象操作の防止)

- **棒グラフの軸は必ず0起点**。0起点にしない折れ線は軸の省略を明示する
- 同じ画面で同じ指標を並べる場合、スケールを揃える(キャンペーンA/Bのグラフで軸が違うと誤読する)
- 期間比較は日数を揃える(28日と31日の月比較には日平均を併記)
- 累計グラフは「右肩上がりに見えて当然」であることに注意。判断用には期間別に直す

## 3. タイトル・ラベルの規律

- タイトルは「何の・どの期間の・どの単位のデータか」まで含める: 「売上」→「**月次売上推移(2025年7月〜2026年6月・税抜)**」
- 指標名の定義注記を必ず付ける(「CV=フォーム送信+電話タップ」「費用=媒体費のみ・手数料抜き」)。**定義のないダッシュボードが数字トラブルの最大の発生源**(`data-reconciliation` の頻出原因)
- 単位は軸またはタイトルに明示(円/件/%)。桁の大きい数字は「万円」表記も検討し、表記を全画面で統一
- 凡例より直接ラベル(線の終端に系列名)を優先。凡例と本体の視線往復を減らす

## 4. 配色の規律

- 色数は最小に: 基本1色+強調1色。系列が4色を超えたらグラフを分ける
- 色に意味を固定する: 自社=濃い主要色 / 比較対象=グレー / 目標=破線。良し悪しを示すときのみ赤(悪化)を使い、装飾に赤を使わない
- 色だけに頼らない(色覚多様性対応): 良し悪しは▲▼や+/-の記号を併記
- 前年・前月の比較系列は薄いグレーで背景化し、当期を主役にする

## 5. Looker Studio等での実装チェックリスト

- [ ] データの鮮度表示(最終更新日時)を画面内に置く
- [ ] 期間フィルタの既定値を利用目的に合わせる(月次判断なら先月、運用なら直近7日)
- [ ] スコアカードの比較期間設定が全カードで統一されているか
- [ ] ブレンドデータの結合キー(日付形式・キャンペーン名)を確認したか(欠損は静かに起きる)
- [ ] 公開前に `data-science/data-reconciliation` で生データと突合したか
- [ ] 閲覧権限が適切か(クライアント向けに社内指標・他社データが見えていないか)

## 6. 公開前レビュー(3問テスト)

1. **3秒**: 初見3秒で「良いのか悪いのか」がわかるか
2. **定義**: 画面内の情報だけで各数字の定義・期間・単位が特定できるか
3. **行動**: このダッシュボードを見た人が「次に何をするか」決められるか(決められないダッシュボードは装飾)
