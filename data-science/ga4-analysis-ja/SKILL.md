# GA4分析スキル

GA4の設定を監査し、意思決定につながる分析を出す。数値の検算・他ツールとの突合は `data-science/data-reconciliation`、レポート化は `management/client-report-generator-ja` に委譲。

## 1. 設定監査(分析の前に必ず)

設定が壊れたGA4を分析しても嘘の結論が出る。初回・四半期ごとにチェック:

- [ ] **キーイベント**(旧コンバージョン)の定義: フォーム送信完了・電話タップ・LINE追加・予約完了が、それぞれ発火条件込みで正しく設定されているか。サンクスページ直アクセスやリロードでの二重計上がないか
- [ ] Google広告とのリンク+キーイベントのインポート(入札最適化に使うイベントの選定は `marketing/google-ads-ja-ops` と整合)
- [ ] 内部トラフィック除外(自社・制作会社・クライアントのIP)。**除外漏れは小規模サイトほど致命的**(月1,000セッションのサイトで社内が2割を占める等)
- [ ] クロスドメイン設定(予約システム・決済が別ドメインの場合。未設定だと予約システムが参照元になりCVの流入元が全部「予約システム」になる)
- [ ] UTMの命名規約: source/medium/campaignの表記ルールを文書化(`line`と`LINE`は別物として集計される。小文字統一を推奨)
- [ ] データ保持期間を14ヶ月に変更(既定2ヶ月のままだと探索レポートで前年比較ができない)
- [ ] URLにメールアドレス等のPIIが載っていないか(GA4規約違反+個人情報保護法リスク。フォームのGET送信が典型)

## 2. GA4特有の落とし穴(誤読防止)

| 現象 | 原因と対処 |
|---|---|
| 数値が日によって欠ける・丸まる | **しきい値**(Googleシグナル有効時の少数データ非表示)。レポート用識別子を「デバイスベース」に切り替えると外れる |
| 探索レポートと標準レポートで数字が違う | サンプリング・処理方式の差。大きな乖離は期間短縮で確認 |
| 参照元 (not set) / direct が多い | 計測タグの実装漏れページ、リダイレクトでのパラメータ消失、アプリ内ブラウザ。タグ網羅を先に疑う |
| 直帰率が低すぎる/高すぎる | GA4の直帰率=非エンゲージメントセッション率(UAと定義が違う)。**エンゲージメント率で語る**方が誤解がない |
| クリック数とセッション数が合わない | 定義が違うのが正常(10〜30%乖離)。`data-reconciliation` の許容誤差表を参照 |
| CVが広告管理画面と合わない | アトリビューション・計上日の違い(GA4はCV発生日、広告はクリック日)。突合はdata-reconciliationで |

## 3. 定型分析メニュー

### A. LP別パフォーマンス(広告運用の基礎資料)
ランディングページ×(セッション/エンゲージメント率/キーイベント/CVR)を流入元別に。CVRの低いLP×高流入の組み合わせが最優先の改善対象(`creative/lp-builder-ja` へ引き継ぎ)。

### B. ファネル分析(探索レポート)
LP到達→フォーム/予約ページ表示→送信完了 のファネルをデバイス別に。**どの段でどのデバイスが落ちているか**まで特定して改善スキルに渡す(フォーム段の離脱→EFO、LP段→FVコピー)。

### C. 流入チャネル評価
デフォルトチャネルグループ+UTM整備済みのカスタム区分で、チャネル×キーイベントを月次比較。organicの内訳(ブランド/一般)はSearch Console連携で補完(`data-science/seo-research-ja` と接続)。

### D. 経路データ(ローカルビジネス)
MEO経由(GBPのUTM付きリンク)、LINE経由を分離して「予約に効いているチャネル」を実数で示す(`marketing/meo-ja` / `marketing/line-official-ja` のKPIと接続)。

## 4. 分析出力の様式

```
## 分析: (問い)(期間、データ取得日)
### 結論(1〜3行。次のアクションが決まる形で)
### 根拠(表・数値。母数を必ず併記 — 率だけで語らない)
### 前提と限界(しきい値・サンプリング・計測範囲の注記)
### 推奨アクション(担当スキルへの引き継ぎ)
```

## 原則

- **母数の小さい率で結論を出さない**(セッション30のCVR比較は無意味)。最低限の母数を結論に併記する。
- 「なぜ下がったか」は、計測要因(タグ・設定変更)→流入要因(広告・季節)→サイト要因(LP変更)の順に切り分ける。計測要因を除外する前にサイト改善を提案しない。
- ダッシュボード化(Looker Studio)する場合、指標定義の注記を必ず入れ、公開前に `data-reconciliation` で突合する。
