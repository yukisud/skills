# 日本語フロントエンドデザインスキル

「AI slop」的な没個性デザインを避け、日本語で読みやすく、意図のあるUIを実装するための指針。

## AIっぽいデザインの兆候(避けるもの)

- 紫→青の同じグラデーション、意味のないガラスモーフィズム
- 絵文字をアイコン代わりに多用
- すべてのセクションが「中央寄せ見出し+3カラムカード」
- 過剰な角丸(rounded-2xl一律)と過剰なドロップシャドウ
- 実在しない実績数字・お客様の声のダミー(特に医療サイトでは法令違反リスク)

代わりに: コンテンツから設計する。トーン(信頼/親しみ/権威)を最初に1語で決め、タイポグラフィ・余白・色の全決定をそのトーンに従わせる。

## 日本語タイポグラフィ(最重要・海外テンプレが壊す部分)

### フォントスタック
```css
font-family: "Hiragino Kaku Gothic ProN", "Hiragino Sans",
             "BIZ UDPGothic", Meiryo, sans-serif;
/* Webフォントを使う場合 */
font-family: "Noto Sans JP", sans-serif; /* サブセット化必須(全ウェイトで数MBになる) */
```
- 英字フォントだけ指定して日本語をOS任せにしない。英字+和文のペアリング時は `font-family: Inter, "Noto Sans JP", sans-serif` の順。
- Noto Sans JPは `font-display: swap` とサブセット(またはGoogle Fontsのtext=指定/unicode-range)でLCP悪化を防ぐ。

### 文字組の数値基準
| 項目 | 日本語の基準 | 補足 |
|---|---|---|
| 本文サイズ | 16px以上 | 14pxは日本語では小さすぎる |
| 行間 | `line-height: 1.7〜1.9`(本文) | 英文の1.5は日本語では詰まりすぎ |
| 見出し行間 | 1.3〜1.5 | |
| 字間 | 本文 `letter-spacing: 0.02〜0.05em`、見出しはやや広め | |
| 一行の長さ | 全角35〜42文字 | `max-width: 40em` 目安 |
| 太字 | 和文は700まで | 900は潰れるフォントが多い |

### 禁則・折り返し
```css
body { overflow-wrap: anywhere; line-break: strict; }
h1, h2, h3 { text-wrap: balance; word-break: auto-phrase; } /* 対応ブラウザで文節折り返し */
```
- 見出しの不自然な折り返しは `<wbr>` か `word-break: auto-phrase` で制御。`<br>` でのモバイル調整はレスポンシブで破綻するため最終手段。
- 約物: カギ括弧・句読点が行頭に来ない(line-break: strict)。感嘆符のあとは全角スペース。

### 和欧混植
- 半角英数字と和文の間にスペースを手打ちしない(将来 `text-autospace` で制御)。数字は半角に統一。
- 日付・金額表記を統一: 「2026年7月13日」「¥33,000(税込)」— 税込/税抜表記は日本の総額表示義務があるため**税込を主表記**にする。

## レイアウト・コンポーネント

- 日本のユーザー向けLPは情報密度をやや高めに許容する(スカスカの欧米風heroだけでは信頼情報が不足しがち)。ただし整理された密度であること: セクション区切り・見出し階層を明確に。
- 信頼要素の定石配置: ファーストビュー直下に「選ばれる理由」ではなく**具体的事実**(実績数・資格・所在地・営業時間)。
- 電話CTA: モバイルは `tel:` リンクの固定フッターが日本のローカルビジネスでは依然CVR最強。タップ領域44px以上。
- フォーム: 姓名分割・フリガナ欄は本当に必要か毎回問い直す(不要なら削る)。郵便番号→住所自動入力。`autocomplete` 属性と `inputmode`(電話は `tel`、郵便番号は `numeric`)を必ず設定。

## DESIGN.md(デザイン指示の属人化を防ぐ)

「いい感じにして」を毎回言い直さないために、プロジェクトルートに `DESIGN.md` を置き、**トークンをYAMLで定義+なぜその値なのかを散文で添える**。以後のUI実装・レビューはこのファイルを正とする:

```markdown
# DESIGN.md
## トークン
​```yaml
color:
  primary: "#1A5276"   # 信頼を最優先するブランドのため彩度を抑えた紺
  accent:  "#E67E22"   # CTA専用。本文・装飾には使わない
font:
  base: '"Noto Sans JP", sans-serif'
  size-body: 16px       # 日本語の可読性下限。これ未満にしない
spacing:
  unit: 8px             # 余白はすべて8の倍数
radius:
  default: 4px          # 角丸は控えめ=誠実さのトーンに合わせる
​```
## トーン
一語で「誠実」。迷ったら装飾を足すのではなく削る。
## 禁止
グラデーション背景 / 絵文字アイコン / 3カラム超のカードグリッド
```

- 新規プロジェクトではUI実装の前にDESIGN.mdを作る(なければこのスキルが提案して作る)。
- 既存サイトの改修では、現状のデザインからトークンを逆抽出してDESIGN.md化してから触る(場当たり的な色・余白の増殖を止める)。
- レビュー(`creative/design-review-ja`)の観点2「トンマナ」はDESIGN.mdとの一致で判定する。

## 品質チェックリスト(実装後)

- [ ] 実機幅375pxで横スクロール・見出し折り返し崩れがない
- [ ] 日本語がOSデフォルト明朝やSerifにフォールバックしていない
- [ ] コントラスト比 4.5:1 以上(WCAG AA)
- [ ] 画像 `alt` が日本語で内容を説明している
- [ ] ダミーの実績・受賞・お客様の声を残していない(プレースホルダは `[要差し替え]` と明示)
- [ ] 医療サイトの場合: 体験談・ビフォーアフター・効果保証の表現をデザイン側でも配置していない(medical-ad compliance は `google-ads-ja-ops` 5章参照)
