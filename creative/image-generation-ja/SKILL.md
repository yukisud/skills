# 画像生成ワークフロースキル

画像生成を「生成ボタン」で終わらせず、**仕様化→生成→検品→修正→後処理**の制作工程として扱う。バナーの企画・法令チェックは `creative/ad-creative-ja`、出来上がりの判定は `creative/design-review-ja` と連携。

## 1. 指示をプロンプトでなく「仕様」に変換する

ユーザーの依頼を受けたら、生成前に必ず以下の5項目へ構造化する(埋まらない項目は用途から推定し、推定と明記):

| 項目 | 内容 | 例 |
|---|---|---|
| Scene | 舞台・状況・時間帯 | 夕方の静かな書斎 |
| Subject | 主役の被写体(数・姿勢・特徴) | ノートPCの前に座る女性、肩までのダークブラウンの髪 |
| Important Details | 外せない要素・質感・色 | 落ち着いたベージュの服、暖色のデスクライト |
| Use Case | 画像の用途(これが構図を決める) | 記事ヘッダー画像 |
| Constraints | サイズ・比率・余白・禁止要素 | 1200×630、右側1/3にタイトル用の余白、文字なし |

### 形容詞を「見える情報」に変換する(最重要ルール)

「おしゃれ」「幻想的」「大人かわいい」「高級感」などの抽象語は、**光・色・構図・質感の具体情報に翻訳してから**プロンプトに入れる:

| 抽象語 | 視覚情報への翻訳例 |
|---|---|
| 幻想的 | 薄い霧、空気中に浮かぶ微細な光、低彩度の青紫、柔らかな被写界深度 |
| 高級感 | 深い影とコントラスト、マットな質感、余白を広く、彩度を抑えた金・黒・白 |
| 親しみやすい | 昼の自然光、暖色系、丸みのあるフォルム、目線の高さのアングル |
| 清潔感 | ハイキー(明るめ露出)、白基調、青系アクセント、整った直線 |
| レトロ | 粒子感、退色したような低彩度、フィルム風の色被り |

ユーザーが「もう少し幻想的に」と言ったら、この翻訳を挟んで具体的な視覚要素の増減として修正指示を組み立てる。

## 2. 用途別ルール

| 用途 | 生成時に固定するルール |
|---|---|
| バナー・広告画像 | 文字を置く余白を指定(入稿サイズは `creative/ad-creative-ja` §3)。被写体を左右どちらかに寄せる。スマホ縮小表示で成立する大きな構図 |
| 記事ヘッダー | タイトル用余白(通常は右または上1/3)。彩度控えめでテキストの可読性を優先 |
| アイコン | 単純なシルエット・1モチーフ。16px相当に縮小しても識別できるか検品。中央配置・余白均等・背景は透過前提のフラット単色 |
| UIモック | 装飾よりレイアウト整合を優先。実データ風の日本語ダミーテキストを指定(lorem ipsumにしない) |
| ゲームアセット | 透過前提(§4)。同シリーズは光源方向・線の太さ・頭身を最初に固定し、全カットで統一 |
| 背景素材 | 主役を置く空間を空ける。タイル利用ならシームレス指定 |

### 日本語テキストの扱い(重要)
画像生成モデルは**画像内の日本語文字を高確率で崩す**。文字入りが必要な場合は「画像は文字なしで生成→文字はHTML/CSS・デザインツールで後乗せ」を原則とする。生成画像に文字を入れる場合は検品で全文字を必ず目視確認する。

## 3. 制作工程(1回の出力で終わらせない)

```
1. 仕様化(§1の5項目) → ユーザーに要旨を1行で確認(自律実行時は仕様を明示して進む)
2. 生成(まず1〜2案)
3. 検品: Constraints充足 / 破綻(手指・文字・パース・左右反転ロゴ) / 用途ルール(§2)
4. 修正: 「維持する要素」と「変更する要素」を分離して指示
   (例: 構図・人物・配色は維持。照明のみ夕方のサイドライトに変更)
5. 後処理: 透過(§4)・リサイズ・圧縮(Web用はWebP/最適化PNG)
6. 納品: ファイル名規約(用途_内容_サイズ.拡張子)で保存し、生成仕様をセットで記録
```

- 修正は1回に1〜2要素まで。全部気に入らない場合は修正でなく仕様(§1)に戻る。
- 採用した仕様は `docs/image-specs/` に保存し、同シリーズの追加生成で再利用する(トーンの一貫性はここで担保)。

## 4. 透過素材のワークフロー(クロマキー方式)

背景透過が必要な素材(アイコン・キャラクター・切り抜き素材)は、透過を直接生成させるより**フラットな単色背景で生成→背景除去**が安定する:

1. 背景を「単色・フラット・影なし」で生成する。背景色は被写体に含まれない色を選ぶ(定番は彩度の高い緑 `#00FF00` または マゼンタ `#FF00FF`)
2. 同梱の `scripts/remove_chroma_key.py` で背景をアルファチャンネル化:
```bash
python3 scripts/remove_chroma_key.py input.png output.png --color "#00FF00" --threshold 60
```
3. 検品: 輪郭のフリンジ(緑残り)を確認。残る場合は `--despill` を付けて再実行、または閾値を調整
4. 被写体に背景色と近い色が含まれる場合は背景色を変えて再生成する

## 5. 権利・法令チェック(納品前)

- [ ] 実在の人物・著名人に似せた生成をしていないか(肖像権・パブリシティ権)
- [ ] 既存キャラクター・ロゴ・ブランド意匠の模倣になっていないか(スタイル指定で特定作家名・作品名を使わない)
- [ ] 使用する生成モデル・サービスの商用利用条件を確認したか
- [ ] 広告利用の場合: 生成画像が事実を誤認させないか(実在しない店舗写真を実店舗のように使う等はNG。`creative/ad-creative-ja` §5の法令チェックを通す)
- [ ] 人物写真風の画像をお客様の声・症例・実績のように見せていないか(景表法・業種規制)
