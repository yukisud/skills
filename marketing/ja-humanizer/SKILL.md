# 日本語ヒューマナイザー

AI生成文特有のパターンを検出し、書き手の意図と情報を保ったまま自然な日本語に書き直す。**内容の改変はしない**(事実・主張・構成の大枠は維持)。

## 検出する「AI臭」パターン(日本語版)

### 語彙・言い回し
- 「〜しましょう」「〜していきましょう」の連発(特に見出し直後)
- 「重要です」「大切です」「欠かせません」の乱用
- 「まとめると」「いかがでしたか」「本記事では〜について解説しました」の定型締め
- 「〜することが可能です」「〜という形になります」「〜を行うことができます」の冗長構文
- 「様々な」「さまざまな」「多くの」の頻出(具体性の欠如)
- 翻訳調: 「〜することを確実にしてください」「〜であることに注意してください」「あなたの」の多用
- カタカナ語の過剰使用(「エンゲージメント」「ソリューション」を和語で言えるのに使う)

### 構造
- 全セクションが同じ長さ・同じ構成(定義→メリット3つ→注意点→まとめ)
- 箇条書きの過剰使用(文章で書くべき論旨まで箇条書き化)
- すべての箇条書きが「体言止め+説明文」の同型
- 各段落の一文目が必ず要約文(トピックセンテンスの機械的反復)
- 「メリット・デメリット」の機械的な対称列挙
- 見出しに番号+コロン形式(「3つのポイント1: 〜」)

### リズム
- 文長が均一(すべて40〜60文字)
- 文末の単調(「です。ます。です。ます。」の交互繰り返しも含む)
- 逆接・転換の接続詞が「しかし」「一方で」しかない

## 書き直しの原則

1. **文末に変化をつける**: 体言止め、疑問形、「〜だ」の混ぜ込み(媒体のトーンが許す範囲で)。
2. **文長に緩急をつける**: 短い断定文を要所に入れる。
3. **一般論を具体に置換**: 「多くの企業が」→ 実数・実例に(元文に情報がなければ書き手に確認する箇所として `[要確認: 具体例]` を残す。**事実の捏造はしない**)。
4. **定型の導入・締めを削る**: 「いかがでしたか」は削除。締めは次の行動か一番伝えたいことの再提示に。
5. **箇条書きの適正化**: 論旨の流れがあるものは文章に戻す。並列事実のみ箇条書きに残す。
6. **話し手の視点を入れる**: 「私たちの現場では」「実際にやってみると」など、書き手固有の視座を1〜2箇所(ペルソナ情報がある場合のみ)。
7. **削る勇気**: ヒューマナイズは通常、文字数が10〜20%減る。水増しの言い換えを足さない。

## やらないこと

- 誤字・崩れ表現をわざと入れる(「人間らしさ」の偽装はしない)
- 事実・数値・固有名詞の変更
- SEO要件の破壊(対象KWが指定されている場合はtitle・hタグ内のKWを維持)
- 医療・法律など規制文脈での表現緩和(断定を強める方向の書き換えはしない)

## 公開前のAI臭スコアリング(検出ゲート)

書き直しだけでなく、既存文が「AIっぽく読まれるか」を公開前に判定する使い方もできる。以下を数え、多いほど要修正:

- [ ] 全角ダッシュ「—」の多用(英語のem dash癖の直輸入。日本語では読点・改行で足りることが多い)
- [ ] 「一方で」「とはいえ」「〜と言えるでしょう」の対比・結びの定型
- [ ] 頼まれていない補足例示(「例えば〜」の乱発)、三点セットの機械的列挙
- [ ] 全段落が同じ長さ・同じ構造(導入文→箇条書き→まとめ の反復)
- [ ] 「重要です」「ポイントは」「〜しましょう」「いかがでしたか」
- [ ] 抽象語の多用(「様々な」「多くの」「効果的な」)で具体が無い

判定は「AI臭: 高/中/低」+該当項目の指摘で返す。**低に至らない場合は書き直しを提案**する(検出だけで終わらせない)。英語コンテンツのレビュー依頼時は、上記の日本語項目を英語のAI tells(em dash、"Moreover/Furthermore"、"It's important to note"、過剰な対比構造)に読み替えて同じゲートを適用する。

## 出力フォーマット

1. **書き直し後の全文**
2. **主な変更点**(パターン別に3〜5項目、Before→Afterの例つき)
3. **要確認箇所**: `[要確認: ]` を残した箇所の一覧
4. 依頼があれば媒体別トーン調整(ブログ/メルマガ/LINE配信/X投稿)
