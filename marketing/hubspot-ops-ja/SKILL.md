# HubSpot運用スキル(日本仕様)

HubSpotの設計・運用を日本の商習慣と法令に合わせて行う。API/MCP連携が使える場合は実データ操作、なければ設計書・設定手順の出力までを担当する。

## 1. プロパティ設計(日本語データの落とし穴)

- **会社名の正規化**: 「株式会社◯◯/◯◯株式会社/(株)◯◯」の表記ゆれで重複コンタクトが量産される。正式名称プロパティと検索用の名寄せキー(法人格除去・全角半角統一)を分ける。法人番号(13桁)を名寄せキーにできれば最強。
- **氏名**: 姓・名を分割し、**フリガナ(セイ・メイ)プロパティを必ず作る**(電話・郵送・営業引き継ぎで必須)。HubSpot標準にはないのでカスタムプロパティで。
- **住所**: 郵便番号→都道府県→市区町村の階層。都道府県は自由入力にせずドロップダウン(47択)にして集計可能にする。
- 電話番号は国内表記(0X-XXXX-XXXX)で統一ルールを決める。全半角混在を許さない。
- プロパティを増やしすぎない。**入力されないプロパティは存在しないのと同じ**。営業が入力するのは5項目以内に絞る。

## 2. ライフサイクルステージとMQL定義

```
Subscriber → Lead → MQL → SQL → Opportunity(商談) → Customer
```

- MQL条件は「スコアX点以上」のような抽象ではなく、**行動の組み合わせで具体的に定義**する(例: 料金ページ閲覧+資料DL、またはセミナー参加)。定義は営業と合意した文書として残す。
- 日本のBtoBは検討期間が長い。MQL未達リードを捨てず、四半期ごとの再ナーチャリング(セミナー案内等)のリサイクル経路を設計する。
- SQL引き渡しのSLAを決める: 「MQL化から営業初回接触まで1営業日以内」等。放置リードの検知ワークフロー(通知)を組む。

## 3. フォームとCVポイント

- フォーム項目は最小に(会社名・氏名・メール・電話の4点から始め、必要が証明されたら足す)。
- **個人情報保護法対応**: フォームに利用目的の明示とプライバシーポリシーへの同意を置く。取得した情報を第三者提供する場合は明示的同意が必要。
- **メール配信同意(特定電子メール法)**: 営業メール・メルマガはオプトインが原則。フォームに配信同意チェックボックスを置き、HubSpotの「マーケティングコンタクト」区分と購読タイプに紐付ける。**チェック済みデフォルトは避ける**(ベストプラクティス上も炎上リスク上も)。
- 名刺・展示会リード: 名刺交換は取引関係の範囲でメール可とされるが、初回メールに配信停止導線を必ず入れ、停止依頼は即時反映する。名刺取込(Sansan等)→HubSpotのインポート時に取得経路プロパティを必ず付ける。

## 4. ワークフロー設計の型

| ワークフロー | トリガー | 内容 |
|---|---|---|
| リード即時対応 | フォーム送信 | サンクスメール+担当者へ通知(Slack/メール)。**日本の商習慣ではリード後の初回接触速度が信頼に直結** |
| ナーチャリング | 資料DL | 3〜5通のステップメール(事例→比較→相談案内)。送信は平日日中、1週間に1通まで |
| MQL昇格 | 条件到達 | ライフサイクル更新+営業割当+SLAタイマー |
| 失注リサイクル | 失注理由=時期尚早 | 90日後に再アプローチタスク |
| ゴミデータ検知 | 定期 | メールバウンス・重複・テスト送信の隔離 |

- メール文面は `marketing/ja-humanizer` で仕上げる。件名は全角15〜20文字目安(スマホでの切れ防止)。
- 全マーケティングメールにフッター(社名・住所・配信停止リンク)。特定電子メール法の表示義務。

## 5. 外部連携の設計

- **広告→HubSpot**: フォームにUTM/GCLID を hidden で保持し、流入元別の商談化率を追えるようにする。
- **HubSpot→Google広告**: 商談化・成約をオフラインコンバージョンとしてインポートし、入札最適化の学習に使う(`marketing/google-ads-ja-ops` と連携)。リード数でなく**商談の質で入札を最適化する**のが本命。
- **レポート**: パイプラインの数値は `data-science/data-reconciliation` で広告側・GA側と突合してから報告に使う。

## 出力様式

設計依頼には「設定手順書」(HubSpot画面の操作単位)+「運用ルール」(誰がいつ何を入力するか)のセットで出す。ワークフロー図はテキストのフロー表記で示し、条件分岐の境界値を明記する。
