# SNSオーガニック運用スキル(日本市場)

広告(`creative/ad-creative-ja`)・LINE(`marketing/line-official-ja`)と別枠の、自社アカウントによる継続発信を設計・運用する。

## 0. アカウント設計(投稿を作る前に)

- 目的を1つに定める: 認知(新規リーチ)/ファン化(既存との関係)/採用/サポート窓口。**目的が違えばKPIも投稿も別物**。混ぜるなら目的別にアカウントを分ける判断も
- プラットフォーム特性(日本):

| 媒体 | 強み | 向く目的 |
|---|---|---|
| X | 速報性・拡散・テキスト文化(日本はX利用が世界的に見ても特に強い) | 認知、ファン化、エンタメ・ゲーム・BtoBナレッジ |
| Instagram | 世界観・ビジュアル・保存 | 店舗・美容・食・EC(プロフィール=ミニLP) |
| TikTok/ショート動画 | フォロワー外への新規リーチ | 認知の初速、若年層 |
| YouTube | 検索性・資産性(ストックになる) | 深い理解・指名獲得 |

- 最初は1媒体に集中。「全部やる」は全部が週1未満になり死ぬ
- プロフィール最適化: 誰向けに何を発信するか+実績+導線リンクを一読で。投稿がバズって流入するのはプロフィールから

## 1. 投稿の設計

- 投稿の型の配合: **役立ち・面白い(価値提供)2 : 舞台裏・人柄(関係構築)1 : 告知・宣伝1以下**。告知だけのアカウントはフォローする理由がない
- 1投稿1メッセージ。冒頭1行(タイムラインで見える範囲)で誰向けかとベネフィットを言い切る
- 継続可能な頻度を設計する(週3を6ヶ月 > 毎日を3週間)。投稿ネタは「よくある質問」「制作過程」「失敗談」「データ」の4系統でストックを作る
- 文体は `marketing/ja-humanizer` を通す(SNSはAI臭への感度が特に高い)。ハッシュタグはXでは0〜2個、Instagramでは絞って関連性の高いものだけ
- トレンド便乗の判断: 自社の文脈と接続できるものだけ。**災害・事件・訃報・政治への便乗は全面禁止**

## 2. 運用ルール(組織として)

- 投稿権限と承認フロー: 誰が下書き、誰が承認、即時投稿できる範囲を文書化(`management/agent-team-orchestration-ja` の権限設計と同様)
- 返信・引用への対応方針を事前に決める: 好意的な言及には反応する/批判には個別判断/議論には参加しない、等
- 中の人の個人色を出す場合、退職時のアカウント帰属を先に決めておく
- ステマ規制: スタッフ・関係者が自社商品を個人アカウントで推す場合も関係性の明示が必要。インフルエンサー依頼は必ず「PR」表記

## 3. 炎上リスク管理

### 投稿前チェック(全投稿)
- [ ] 政治・宗教・ジェンダー・容姿・国籍に触れる表現はないか(意図せぬ文脈でも)
- [ ] 誰かを下げて笑いを取っていないか(自虐はOK、他虐はNG)
- [ ] 数字・事実の誤りはないか(訂正投稿は拡散で追いつけない)
- [ ] 顧客・取引先が特定できる情報はないか(店内写真の映り込み含む)
- [ ] 大きな事故・災害の直後でないか(予約投稿の停止確認)

### 炎上初動(発生時)
1. **すぐ消さない・すぐ反論しない**。まず事実確認(何が・どこまで拡散し・批判の論点は何か)
2. 自社に非がある → 24時間以内に謝罪と対応を投稿(部分的な非なら、非がある部分を特定して謝る)。削除する場合は削除の旨を明記してから(黙って消すと二次炎上)
3. 事実誤認による批判 → 事実を淡々と1回説明。論戦はしない
4. 誹謗中傷・脅迫 → スクリーンショットで証拠保全→法的対応の検討。個別に反応しない

## 投稿案の出力様式

投稿案を依頼されたら以下のセットで出す(本文だけ出さない):

```
### 案N(型: 役立ち/舞台裏/告知)
- 本文: (そのまま投稿できる完成形。媒体の文字数内)
- 画像・動画指示: (必要な場合。image-generation-ja へ渡せる粒度で)
- 狙い: (誰に何を起こしたいか1行)
- 投稿前チェック: (§3のチェック結果。特記なければ「問題なし」)
```

## 4. 計測と月次レビュー

- 見る指標: フォロワー数より**エンゲージメント率・プロフィールアクセス・リンク遷移・保存数**(目的に応じて主KPIを1つ)
- 月次で「投稿の型×反応」を集計し、勝ちパターンを翌月の配合に反映。伸びた投稿は同型の変奏を作る
- SNS経由の流入・CVは `data-science/ga4-analysis-ja` のUTM規約で分離計測
- 報告は `management/client-report-generator-ja` の様式で(バズの瞬間風速でなく傾向で語る)
