# 除外キーワードスキャナー(日本語対応)

検索語句レポート(CSV/スプレッドシート/貼り付けテキスト)を受け取り、除外キーワード候補を根拠付きでリスト化する。

## 入力

想定カラム: 検索語句、表示回数、クリック数、費用、コンバージョン数(、キャンペーン/広告グループ)。
カラム名が英語(Search term, Cost, Conversions)でもそのまま処理する。費用の単位は円とみなす。

## 検出ロジック

### 1. 無関係インテント検出
ビジネスの提供内容と一致しない検索意図を分類する。業種を問わず頻出のパターン(店舗・EC・BtoB共通):

| カテゴリ | 例 | 判定 |
|---|---|---|
| 求人・採用系 | 「◯◯(職種名) 求人」「〜 バイト」「〜 年収」「〜 募集」 | 求人サイトでない限り除外 |
| 学習・資格系 | 「〜 なり方」「〜 国家試験」「〜 専門学校」 | 除外 |
| DIY・自力解決系 | 「〜 自分で」「〜 やり方」「〜 無料ツール」 | 原則除外(コンテンツ集客なら残す判断も) |
| 情報収集のみ | 「〜とは」「〜 意味」「〜 原因」 | CVR実績を見て判断(即除外しない) |
| 価格比較の圏外 | 「〜 無料」「〜 激安」(高単価商材の場合) | ビジネスモデルと照合して判断 |
| 地域外 | 商圏外の地名を含むクエリ | 除外(地域名の同名異地に注意: 例「府中」は東京と広島) |
| 競合指名 | 他社名・他店名 | 戦略判断。医療など信頼が重要な業種では競合名入札が炎上リスクになるため原則除外推奨 |

### 2. 高消化ゼロCV検出
- 費用が目標CPAの50%を超えていてCV=0のクエリを抽出。
- ただし**インテントが合っているクエリは即除外しない**。「除外」ではなく「監視リスト」に分類し、目標CPAの100%超過で除外提案。

### 3. 日本語表記ゆれの統合判定
日本語は同一意図が複数表記で出る。除外判定・除外登録の両方で考慮する:
- ひらがな/カタカナ/漢字: 「入れ歯/いれば」「ほわいとにんぐ/ホワイトニング」
- 送り仮名・長音: 「問い合わせ/問合せ」「サーバー/サーバ」
- 略語: 「インビザ/インビザライン」
- **除外登録時**: フレーズ一致の除外は表記ゆれに効かない。主要な表記ゆれパターンを列挙して登録する必要がある旨を出力に含める。

### 4. 除外済みとの重複チェック
既存の除外KWリストが渡された場合、重複候補を除いて差分のみ提案する。

## マッチタイプの推奨基準

| 状況 | 推奨 |
|---|---|
| 単語自体が常に無関係(「求人」「無料」等) | **フレーズ一致**でアカウント共有リストへ |
| 特定の組み合わせのみ無関係 | フレーズ一致でキャンペーン単位 |
| 完全に特定クエリだけ止めたい | 完全一致 |

部分一致除外は日本語では想定外の広がり方をするため原則使わない。

## 出力フォーマット

```
## サマリ
- 分析クエリ数 / 除外候補数 / 削減見込み費用(月換算・円)

## 除外候補(即時対応)
| 検索語句 | 費用 | CV | 分類 | 除外KW(登録する語) | マッチタイプ | 登録先 | 根拠 |

## 監視リスト(今回は除外しない)
| 検索語句 | 費用 | CV | 次回判断基準 |

## 表記ゆれ補足
(除外KWごとに追加登録すべき表記バリエーション)

## 追加提案
(共有リスト化の提案、構造的な問題があればマッチタイプ・KW構成への示唆)
```

## 注意

- 除外のしすぎは学習データを痩せさせる。1回の提案で表示回数上位80%をカバーする範囲に留め、ロングテールの1クリッククエリを個別除外で追いかけない。
- CV計測に電話CVが含まれていない場合、ゼロCV判定が過剰になる。計測範囲を最初に確認し、レポートに前提として明記する。
