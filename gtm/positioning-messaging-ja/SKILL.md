# ポジショニング&メッセージング設計スキル

「何を・誰に・どう言うか」を1つの文書(メッセージングフレームワーク)に固め、全チャネルのコピーの親にする。GTMで最もレバレッジが大きい上流工程。ここが曖昧なままLPや広告を作ると、チャネルごとにバラバラの訴求が生まれて検証が効かなくなる。

## 1. インプットの収集(机上で作らない)

優先順位順に:
1. **顧客の生の言葉**: 問い合わせ文面、商談録、口コミ、アンケート自由回答。「選んだ理由」「迷った他の選択肢」「決め手」を抽出する
2. 競合の訴求(`gtm/competitor-analysis-ja` の出力)
3. 検索クエリ(検索語句レポート・サジェスト): 市場が使っている言葉そのもの
4. 社内の思い(最後。社内が言いたいことと市場が聞きたいことを混同しない)

顧客データが一切ない新規事業の場合は仮説として作り、**全項目に「検証方法」を付ける**。

## 2. ポジショニングの決定

- **競合の再定義**: 真の競合は同業他社とは限らない。「何もしない」「自力でやる」「別カテゴリの代替手段」を必ず候補に入れる(例: 歯科矯正の競合はマウスピース通販と「放置」)。
- **ポジショニングステートメント**:
  「(ターゲット)にとって、(サービス)は、(競合・代替手段)と違い、(独自の価値)を提供する(カテゴリ)である。なぜなら(証拠)があるからだ。」
- 独自の価値は**相手が乗り換え・行動するに足る差**か検証する。自社が言える差ではなく、顧客が気にする差を選ぶ。
- 日本市場の注意: 「業界初」「No.1」をポジショニングの核にする場合、景表法上の客観的根拠(調査データの出典・範囲・時期)が揃うかを先に確認する。揃わないなら核にしない。

## 3. メッセージングフレームワーク(成果物の本体)

```
## メッセージングフレームワーク: (サービス名) vYYYY.MM
### コア
- ポジショニングステートメント
- タグライン候補(3案。全角15字前後だと広告見出しにそのまま使える)

### 訴求の優先順位(3階層)
| 順位 | 訴求(主張) | 証拠(事実・数字) | 顧客の言葉での言い換え | 使う場面 |
| 1(主訴求) | | | | FV・広告見出し |
| 2(支持訴求) | | | | LP中盤・説明文 |
| 3(補強) | | | | FAQ・営業トーク |

### 反論処理マップ
| よくある不安・反論 | 返す事実 | 掲載場所 |

### 言葉遣いの規定
- 使う言葉/使わない言葉(顧客語彙 vs 社内語彙の対訳表)
- トーン(です・ます/専門度/一人称)
- NG表現(法令: 医療広告GL・薬機法・景表法に触れる表現のリスト)

### ターゲット別の変奏(必要な場合のみ)
(例: 患者本人向け/家族向け で主訴求の順位がどう入れ替わるか)
```

## 4. チャネルへの展開ルール

- 広告見出し(`marketing/rsa-copywriter-ja`)・LPのFV(`creative/lp-builder-ja`)・営業資料の表紙(`creative/sales-deck-ja`)は**必ず主訴求から作る**。各スキルにこの文書を渡して起動する。
- 「証拠」列が空欄の主張はどのチャネルにも出さない。
- 変更管理: 訴求の変更はこの文書を先に更新→各チャネルへ反映の順。チャネル側で勝手に新訴求を発明したら、この文書に取り込むか棄却するかを判断する。

## 5. 検証と改訂

- 主訴求はコピーテストで検証する(広告なら見出しA/B、LPならFVテスト)。**感想でなくCTR・CVRで判定**。
- 四半期に一度、実際の顧客獲得理由(商談録・アンケート)と主訴求を突合し、ズレていたら改訂する。フレームワークは「完成させるもの」ではなく「運用するもの」。
