# クライアント報告書生成スキル(日本仕様)

生データ(CSV、スプレッドシート、管理画面の数値)から、そのまま送れる品質の報告書ドラフトを作る。

## 入力の確認

- 対象期間と比較軸(前月比を基本、季節性のある業種は前年同月比を併記)
- クライアントの理解度(専門用語をどこまで使えるか)。不明なら**平易寄り**に倒す
- 前月の報告書(あれば): 「翌月の施策」に書いた項目の実施結果を必ず今月の報告で回収する

## 報告書の構成(この順で)

### 1. 今月のサマリ(3行以内)
- 良かったこと1つ、課題1つ、来月やること1つ。数字は最重要の1〜2個だけ。
- クライアントがここしか読まなくても意思疎通が成立するように書く。

### 2. 主要数値(表)
| 指標 | 当月 | 前月 | 前月比 | 目標 | 達成率 |

- 指標は**クライアントの利益に近い順**に並べる: CV数(予約数・問い合わせ数)→CPA→費用→クリック→表示。表示回数から始めない。
- 金額は円・税抜/税込を明記。パーセントは小数1桁まで。
- 増減には必ず**理由を1文**添える。理由が不明な変動は「調査中」と正直に書き、放置しない。

### 3. 分析(何が起きたか)
- 「事実→解釈→対応」の順で書く。事実と解釈を混ぜない。
- グラフ指定がある場合: 推移は折れ線、構成比は横棒(円グラフは3項目まで)、目標との比較は棒+目標線。
- 悪い数字を隠さない。**悪化の報告は「悪化の事実+原因仮説+対応策」を必ずセット**にする(対応策のない悪化報告を出さない)。

### 4. 実施した施策と結果
- 前月報告で予告した施策の実施状況(実施済/実施中/未着手と理由)
- 各施策の効果測定(効果が出るまでの期間も明記し、早計な判断をしない)

### 5. 翌月の施策(3件以内)
- 各施策に「目的・作業内容・期待効果・クライアント側にお願いすること」を書く。
- クライアント側の作業(素材提供、LP修正の承認等)があるものは**依頼事項として独立させ、期日を付ける**。

### 6. 補足・トピック
- 市場動向、競合の動き、Google側の仕様変更でクライアントに影響があるもののみ。

## 文章のルール

- です・ます調で統一。社外文書として敬語を正しく(「させていただく」の乱用は避ける)。
- 専門用語は初出時に括弧で平易な説明を付ける: 「CPA(お問い合わせ1件あたりの広告費)」「インプレッション(広告の表示回数)」。
- 責任の所在を曖昧にする表現(「〜と思われます」の連発)を避け、根拠の強さに応じて言い切る/仮説と明示するを使い分ける。
- 数値の捏造・見栄えのための丸めは絶対にしない。データが欠けている場合は欠けていると書く。

## 出力形式

- 既定はMarkdown(そのままドキュメント化・PDF化できる構造)。指定があればスライド構成案(1スライド1メッセージ)やメール本文形式に変換。
- 冒頭に宛名・期間・作成日を入れる:

```
株式会社◯◯ 御中
◯◯運用レポート(2026年6月度)
作成日: 2026年7月◯日 / 作成: ◯◯
```

## 品質チェック(送付前)

- [ ] サマリだけ読んで今月の状況がわかるか
- [ ] 全ての悪化指標に原因と対応策が付いているか
- [ ] 前月予告した施策をすべて回収したか
- [ ] クライアント依頼事項に期日があるか
- [ ] 医療クライアントの場合、報告書内の広告文引用が院内資料として問題ないか
