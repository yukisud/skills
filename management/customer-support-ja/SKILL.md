# カスタマーサポートスキル(日本仕様)

獲得(マーケ)の後工程である「対応品質」を設計する。日本市場は対応品質への期待水準が高く、**対応の良さが口コミ(`marketing/meo-ja`)とリピート(`marketing/line-official-ja`)に直結する**。文面の敬語は `management/business-email-ja` に準拠。

## 1. 一次対応の型(全問い合わせ共通)

```
1. 感謝(問い合わせ・指摘そのものへ)
2. 事実の確認(相手の状況を要約して認識合わせ。思い込みで回答しない)
3. 回答 or 対応の提示
4. 即答できない場合: 「いつまでに・誰が・何を」回答するかを必ず約束する
   (「確認します」で終わらせない。期日のない保留が不信の最大要因)
5. 追加の問い合わせ先
```

- 初回応答の速さは解決の速さと同じくらい満足度に効く。**当日中(営業時間内なら数時間以内)の一次返信**を標準にする(解決していなくても「受け取った+期日」を返す)
- 回答は結論から。長い経緯説明を先頭に置かない

## 2. クレーム対応

### 切り分け(最初にやる)
| 分類 | 対応方針 |
|---|---|
| 自社に非がある | 迅速な謝罪+是正+再発防止の提示 |
| 期待値のズレ(非はないが不満は事実) | 不快にさせたことへの共感+事実の丁寧な説明+今後の改善検討 |
| 誤解・事実誤認 | 反論せず事実を提示。「お客様が間違っている」と言わずに正しい情報へ導く |
| 不当要求(カスハラ) | §3へ。通常クレームと同じ土俵で対応しない |

### 対応の原則
- **部分謝罪を使い分ける**: 全面的な非を認める前でも「ご不便をおかけしていること」への謝罪はできる。事実確認前に責任の所在まで認めない(「私どもの不手際で」は確認後に)
- 感情と事実を分けて聞く。感情には共感、事実には調査で応える
- 対応記録を必ず残す(日時・内容・対応者・約束事項)。口頭対応も直後に記録
- 金銭対応(返金・値引き)は承認ルートを事前に定義し、担当者の場当たり判断でやらない。返品・キャンセル条件は特商法・自社規約に沿って一貫させる(人によって違う対応が一番危険)
- 謝罪文面の構成は `management/business-email-ja` の謝罪の型(事実→謝罪→原因→対応→再発防止)。重大案件は文面だけで完結させず電話・対面を添える

## 3. カスハラ(不当要求)への対応基準

通常のクレームと不当要求を区別し、後者には毅然と対応する(従業員保護は企業の義務):
- **打ち切り基準を事前に文書化**: 土下座等の要求/長時間・繰り返しの拘束/暴言・脅迫/SNS拡散を材料にした要求 → 「これ以上のご対応はいたしかねます」で対応を終了してよい
- 対応は複数人・記録前提で。担当者ひとりに抱えさせない(電話は録音の告知、対面は2名)
- 脅迫・業務妨害は証拠保全(録音・スクリーンショット)→警察・弁護士へ。ネット上の誹謗中傷は発信者情報開示の選択肢も
- 対応者のケアも仕組みに入れる(報告して交代できるルール)

## 4. 仕組み化(対応を資産にする)

- **同じ問い合わせが3回来たらFAQ化**する(サイトFAQ・LINEリッチメニュー・自動応答へ)。FAQは質問を顧客の言葉で書く(社内用語で書かない)
- 問い合わせログを月次で分類集計: 商品起因/説明不足起因/操作起因。**説明不足起因はLP・FAQの改善タスク**として `creative/lp-builder-ja` 等へ引き継ぐ(サポートはプロダクト改善の入力源)
- 対応テンプレートを整備しつつ、コピペ感を出さない(宛名・状況の要約は必ず個別に書く)
- クレームからの改善事例は `gtm/customer-research-ja` の「不安・障壁」データとしても蓄積する

## 出力様式

文面作成の依頼には「そのまま送れる文面+対応方針の要約(分類・約束した期日・記録すべき事項)」のセットで返す。体制設計の依頼には対応フロー図(分類→担当→エスカレーション基準)と打ち切り基準の文書を納品する。
