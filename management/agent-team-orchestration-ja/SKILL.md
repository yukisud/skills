# AIチーム編成スキル(AI社員化)

複数エージェントに役割を与えて業務を分担・レビューさせるための設計図。日本の組織運営の型(役割の明確化・報連相・承認フロー)をエージェント運用に写し取ったもの。

## 基本原則

1. **推論・実働・レビューの3層分離**: 同じエージェントに「作らせて」「自分で検品させる」ことをしない。作成者とレビュアーは必ず別インスタンスにする。
2. **1エージェント=1責務**: 「マーケ全部やる係」ではなく「除外KW監査係」「RSA作成係」のように、入力と出力が定義できる単位で切る。
3. **人間の承認ゲートを明示**: 外部に出るもの(広告入稿、クライアント送付、公開)は必ず人間の承認を挟む。エージェントには「承認待ちで停止する」ことを役割定義に書く。
4. **監査可能性**: 全エージェントの実行は `command-logger` でログを取り、誰(どの役割)が何をしたか追跡できるようにする。

## 役割定義テンプレート

エージェント1体につき以下を定義する(サブエージェント定義ファイルやタスクプロンプトに転記する):

```markdown
## 役割名: (例: 除外KW監査担当)
- 使命: (1文。何のために存在するか)
- 入力: (受け取るもの。形式まで指定: 検索語句CSV等)
- 出力: (納品物。形式・置き場所まで指定)
- 使用スキル: (例: marketing/negative-keyword-scanner)
- 権限: (読み取りのみ/書き込み可/実行可。最小権限で)
- してはいけないこと: (例: 除外KWの本番登録。提案までで停止)
- エスカレーション条件: (例: 削減見込みが月5万円を超える提案は人間承認へ)
- 完了報告の形式: (下記「報告様式」)
```

## タスクライフサイクル

```
起票 → 割当 → 実行 → セルフチェック → レビュー(別エージェント) → 人間承認(必要時) → 完了報告
```

- **起票**: タスクには「完了条件」を必ず書く。「〜を検討する」は完了条件にならない。「除外候補リストをマッチタイプ付きで納品」のように書く。
- **引き継ぎ**: エージェント間の受け渡しは自然文の要約ではなく、**構造化した引き継ぎ文書**で行う(下記)。コンテキストは引き継がれない前提で、前提条件・制約をすべて書く。
- **レビュー**: レビュアーには「承認/差し戻し」の二値で判定させ、差し戻し時は箇所と理由を必須にする。レビュー往復は2回まで。2回で通らなければ人間へエスカレーション。

### 引き継ぎ文書テンプレート
```markdown
## 引き継ぎ: (タスク名)
- 依頼元 → 依頼先:
- 背景: (なぜこのタスクが存在するか。2〜3行)
- 入力物: (パス・データの所在)
- 完了条件:
- 制約: (法規制・トーン・締切・触ってはいけないもの)
- 判断に迷ったら: (エスカレーション先と基準)
```

## 報告様式(報連相の型)

エージェントの完了報告は以下の順で統一する:
1. **結論**: 完了/一部完了/ブロック中
2. **成果物**: 場所と形式
3. **判断したこと**: 実行中に裁量で決めた事項(承認者が把握すべきもの)
4. **懸念・申し送り**: 次工程やレビュアーへの注意点
5. **未対応**: スコープ外として残したもの

「問題ありません」だけの報告を禁止する。何を確認した上で問題ないのかを書かせる。

## 編成パターン例(広告運用チーム)

| 役割 | 層 | 使用スキル | 権限 |
|---|---|---|---|
| 運用ストラテジスト | 推論 | google-ads-ja-ops | 読み取りのみ |
| 検索語句監査 | レビュー | negative-keyword-scanner | 読み取りのみ |
| 広告文ライター | 実働 | rsa-copywriter-ja | 下書き作成まで |
| コンプラ検査 | レビュー | rsa-copywriter-ja(チェック章) | 読み取りのみ |
| レポート作成 | 実働 | client-report-generator-ja | ドラフト作成まで |
| 人間(あなた) | 承認 | — | 入稿・送付の実行 |

## アンチパターン

- 巨大な1エージェントに全部やらせる(コンテキスト崩壊・責任不明)
- レビュアーを省略して速度を優先(外部に出る成果物では絶対にしない)
- エージェント数を先に決めて仕事を後から探す(業務分解が先、編成は後)
- 人間の承認ゲートをエージェントの自己申告に置き換える
